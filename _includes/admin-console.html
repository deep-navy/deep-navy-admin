Check-run trust

2 models

The same shape of evidence — a green check run — trusted two different ways. The review gate pins the publisher to the platform App; objective acceptance deliberately does not, because GitHub Actions publishes as its own app, and replaces the pin with four checkable constraints.

deep-navy/review-gatepublisher pinned

Trust is the publisher. The gate is satisfied only by a check run whose github_app_id is the platform App’s integration id — no other app, workflow or bot can satisfy it, whatever it names its check.

  • github_app_id = the platform App — the single test
deep-navy/objective-<uuid>no app pin — deliberate

GitHub Actions publishes check runs as its own app, so an app pin would reject every legitimate acceptance run. Trust is four checkable constraints instead:

  • name matches deep-navy/objective-<uuid>
  • head SHA verified on the default branch — in SQL, not from the payload
  • team ↔ repository tenancy fence
  • monotonic observed_at — an older delivery never overwrites a newer verdict

PRD sign-off lock contract

4 statuses

On approval the platform locks the PRD discussion out-of-band and certifies its integrity. Responses dispatch on the status string, never the HTTP code alone — the two 409s share a code, and only one of them heals.

POST /internal/v1/prd-signoff-locks
certifies
"status": "locked"
Discussion locked and integrity certified. Returns locked, body_sha256 (the 64-hex signed record) and user_content_edit_count.
HTTP 200
retryable
"status": "discussions_permission_missing"
The customer org has not accepted the Discussions grant yet. Self-heals when the org grant lands — keep retrying; do not surface an error.
HTTP 409
permanent
"status": "token_scope_unavailable"
The token cannot carry the Discussions scope at all. Retrying cannot change this.
HTTP 409
permanent
"status": "discussion_not_found"
The referenced discussion does not exist. There is nothing to lock — permanent, not retried.
HTTP 404
